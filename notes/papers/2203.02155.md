# Training language models to follow instructions with human feedback（InstructGPT）

> 把 GPT-3 变成 InstructGPT 的三步法：人工示范做 SFT，人工排序训数据训奖励模型（RM），再用 PPO 对 RM 做强化学习——这是 [[rlhf]] 的奠基性工程论文，后来几乎所有后训练流水线的"标准起点"。

## 元信息

- 机构：OpenAI
- 发表：2022-03-04（arXiv v1）
- 链接：[arXiv](https://arxiv.org/abs/2203.02155) · [Code](https://github.com/openai/following-instructions-human-feedback)
- 对比基线：GPT-3（175B，直接提示 / few-shot 提示）、175B GPT-3 在 FLAN / T0 数据集上微调的版本
- 产出模型：1.3B / 6B / 175B 三个规模的 InstructGPT，论文默认指"PPO-ptx"变体

## 要解决的问题

把"预测下一个 token"的预训练目标和"按用户意图、有帮助、诚实、无害地响应"的目标对不齐（misalignment）。单纯把模型做大不会自动解决这个问题：GPT-3 常常编造事实、生成有毒内容、或者根本不按指令做事。本文的做法是用人类反馈直接微调，而不是堆更大的模型。

## 方法

标准三步法（Figure 2），本文把它系统化、跑通到 175B 规模：

1. **Step 1 — SFT（监督微调）**：标注员针对 API 提交的 prompt 分布写"示范输出"，直接用监督学习微调 GPT-3。训了 16 epoch，cosine 学习率衰减，残差 dropout 0.2；在验证集 loss 上 1 个 epoch 后就过拟合，但继续训更多 epoch 仍能提升 RM 分数和人工偏好评分。
2. **Step 2 — RM（奖励模型）训练**：从去掉最后 unembedding 层的 SFT 模型初始化，输出一个标量奖励。只用 6B 规模（175B RM 训练不稳定，不适合做 RL 里的 value function）。标注员对同一 prompt 的 K=4~9 个回复排序，产生 $\binom{K}{2}$ 个比较对；关键工程细节是把同一 prompt 的所有比较对打包成**一个 batch element**而不是拆成独立样本——否则同一补全会被用于 K-1 次梯度更新，单个 epoch 内就过拟合。损失函数：
   $$\text{loss}(\theta) = -\frac{1}{\binom{K}{2}} \mathbb{E}_{(x,y_w,y_l)\sim D}\left[\log\left(\sigma(r_\theta(x,y_w) - r_\theta(x,y_l))\right)\right]$$
   其中 $r_\theta(x,y)$ 是 RM 对 prompt $x$、补全 $y$ 的标量输出，$y_w$ 是偏好更高的补全。RM 损失对奖励整体平移不变，所以训练前用 bias 把示范数据的平均分归一化到 0。
3. **Step 3 — PPO 强化学习**：把 SFT 模型在一个 bandit 环境（给一个 prompt → 生成一个回复 → RM 打分 → episode 结束）里用 PPO 继续优化，value function 从 RM 初始化。每个 token 加一个相对 SFT 模型的 KL 惩罚，防止策略过度利用 RM 的漏洞（reward hacking）。联合目标：
   $$\text{objective}(\phi) = \mathbb{E}_{(x,y)\sim D_{\pi_\phi^{RL}}}\left[r_\theta(x,y) - \beta\log\left(\pi_\phi^{RL}(y|x)/\pi^{SFT}(y|x)\right)\right] + \gamma\,\mathbb{E}_{x\sim D_{pretrain}}\left[\log(\pi_\phi^{RL}(x))\right]$$
   纯 PPO 模型 $\gamma=0$；加入预训练分布上的似然梯度（混入预训练更新）得到"PPO-ptx"，用于缓解在公开 NLP 数据集上的性能回退（alignment tax）。Step 2/3 可以迭代：用当前最优策略采样新的比较数据，训新 RM，再训新策略。

系统流程（简化）：

```mermaid
flowchart LR
    A[预训练 GPT-3] --> B["Step 1: SFT<br/>人工示范"]
    B --> C["Step 2: 训练 RM<br/>人工排序 K=4~9 个回复"]
    C --> D["Step 3: PPO<br/>以 RM 为奖励 + KL 惩罚"]
    D -. "迭代: 采样新比较数据" .-> C
    D --> E[InstructGPT / PPO-ptx]
```

## 实验与结果

- **偏好胜率**：175B InstructGPT 输出在 85±3% 的情况下被标注员偏好于 175B GPT-3 直接输出，71±4% 的情况下偏好于精心构造的 few-shot GPT-3；**1.3B 参数的 InstructGPT 输出被偏好于 175B GPT-3**，参数量差 100 倍以上（Figure 1）。
- **真实性**：TruthfulQA 上 InstructGPT 生成真实且有信息量答案的比例约为 GPT-3 的两倍；闭域任务（摘要、闭域 QA）的幻觉率从 GPT-3 的 41% 降到 InstructGPT 的 21%。
- **毒性**：在"请礼貌回答"的提示下，RealToxicityPrompts 上 InstructGPT 比 GPT-3 少生成约 25% 的有毒内容；但去掉"礼貌"提示后优势消失，且**被明确要求生成有毒内容时，InstructGPT 比 GPT-3 更毒**——对齐并不等于无法被诱导。偏见（Winogender、CrowS-Pairs）没有明显改善。
- **Alignment tax 与计算成本**：默认 PPO 微调会导致 SQuAD、DROP、HellaSwag、WMT'15 法英翻译等公开 NLP 数据集上性能下降，即"对齐税"；混入预训练梯度（PPO-ptx）能大幅缓解，且不损失标注员偏好分数，效果优于单纯调大 KL 系数。**算力对比是全文最值得记的数字**：175B SFT 训练需要 4.9 petaflops/s-days，175B PPO-ptx 训练需要 60 petaflops/s-days，而 GPT-3 预训练需要 3,640 petaflops/s-days——后训练的算力成本只是预训练的 1.6%（60/3640），但效果超过把模型做大 100 倍。
- **数据规模**：SFT 数据集约 1.3 万 prompt，RM 数据集约 3.3 万 prompt，PPO 数据集约 3.1 万 prompt（仅来自 API，无人工标签）。
- **泛化性**：对未参与训练的"held-out"标注员，InstructGPT 相对 GPT-3 的偏好优势基本不变；5-fold 交叉验证下 RM 预测held-out 标注员偏好的准确率为 69.6±0.9%，仅比训练集内的 72.4±0.4% 略低。标注员之间一致率约 72.6%~77.3%。
- **跨域泛化**：InstructGPT 能一定程度遵循非英语指令、总结和回答代码相关问题，尽管这些类型在微调数据中占比极小——说明"follow instructions"这个能力本身有一定泛化性，不是纯粹的记忆匹配。

## 局限与疑点

- **标注员代表性有限**：约 40 名标注员，主要是英语母语、居住在美国或东南亚（通过 Upwork / Scale AI 招募），标注结果带有这个特定群体的价值判断，论文自己承认"对齐的是这群标注员的偏好，而非某种普适的人类价值观"。
- **多数比较只有 1 个标注员标注**（成本原因），标注员之间分歧未被充分建模，论文承认"按平均偏好对齐"在分歧较大时未必是合理策略。
- **"对齐"≠"安全"**：模型在大多数情况下服从用户指令，即使指令本身有害（如被要求"尽量生成有偏见内容"时反而比 GPT-3 更极端）；论文明确把"拒绝有害指令"列为未来工作而非本文范围。
- 仍会编造事实、过度说模棱两可的话（hedging）、处理多重显式约束时表现差（如"列出 10 部 1930 年代法国背景的电影"）。
- RM 只用了 6B 规模（175B 不稳定），这个工程限制本身也说明 RM 训练在当时的稳定性是个开放问题。

## 对我们的启发

这篇论文本身是训练算法/对齐方法论文，不直接讲基础设施，但三个数字和一个结构对我们判断"后训练流水线要补什么能力"很直接：

1. **后训练的算力密度远低于预训练，但迭代频率远高于预训练**：60 petaflops/s-days 相当于 GPT-3 预训练的 1.6%，意味着一次完整的 RLHF 迭代（collect comparisons → train RM → PPO）在算力上是"轻量级、可以频繁跑"的任务。对我们的沙箱/调度平台来说，这类工作负载的特征是「GPU 用量小但迭代轮次多、对排队延迟敏感」，跟预训练的"长时间占满整卡"完全是两种调度画像，值得单独建队列/配额策略，而不是复用预训练的大批量调度逻辑。
2. **PPO 的 rollout 环境是一个"bandit"（单轮、无状态）**：prompt → 一次生成 → 一次 RM 打分 → episode 结束，没有多轮交互、没有工具调用、没有环境状态持久化。这是最简单的 agentic RL 环境形态，是我们理解后续 agentic RL（多轮、带工具、带执行环境）复杂度增量的基线：对比 [[grpo]] 等后续方法面对的多轮 rollout 场景，这篇论文的"单轮 bandit"说明早期 RLHF 根本不需要会话级沙箱隔离、不需要环境快照/恢复——这类能力需求是后来 agentic RL（多轮工具调用、代码执行）才引入的,帮我们判断"这个能力是从什么时候、为了解决什么问题才变得必要"。
3. **RM 训练的 batch 打包技巧**（把同一 prompt 的 $\binom{K}{2}$ 个比较对打包成一个 batch element 而非独立样本）是个纯训练工程优化，但提示我们：**凡是"同一输入、多个采样结果互相比较"的训练范式（RM 训练、GRPO 的组内比较），都存在"重复利用同一次前向计算"的优化空间**，调度/批处理层如果能感知这种数据结构（而不是把每个比较对当独立请求派发），能省下大量重复计算，这是我们设计 rollout/训练数据派发接口时可以提前考虑的抽象。

- 调研 RLHF 之后 DPO / RLAIF 等"去掉显式 RM 或去掉 PPO"的后训练方法，对比它们对训练系统（是否还需要独立的 RM 推理服务、是否还需要 PPO 的 rollout-训练分离）提出的基础设施要求有何不同。
- 整理一张"后训练算法的 rollout 环境复杂度"时间线（InstructGPT 的单轮 bandit → RLVR/GRPO 的单轮多样本 → agentic RL 的多轮工具调用），标出每一跳对沙箱/执行环境提出的新能力要求。
