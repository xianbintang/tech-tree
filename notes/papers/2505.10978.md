# Group-in-Group Policy Optimization for LLM Agent Training

> 在不增加 rollout、不引入 critic 的前提下，通过"回溯识别轨迹间重复出现的环境状态"给 [[grpo]] 补上一层 step 级相对 advantage，解决多轮 agent 训练里的稀疏奖励信用分配问题。

## 元信息

机构：南洋理工大学 + Skywork AI / 发表：2025-05-16（v3 2025-10-28）/ 链接：[arXiv](https://arxiv.org/abs/2505.10978) · [Code (verl-agent)](https://github.com/langfengQ/verl-agent) / 对比基线：PPO（带 critic）、RLOO、[[grpo]]、RAGEN 的 trajectory-level GRPO

## 要解决的问题

组内相对 advantage（[[grpo]]、RLOO 等 group-based RL）在数学推理、代码生成这类单轮任务上很成功：一个 prompt 采样一组完成，用组内均值/标准差归一化奖励即可，critic-free、低显存、训练稳定。但把这套方法直接搬到多轮 agent 训练（ALFWorld 可达 50 步、2 万+ token 一条轨迹）时会失效：GRPO 把整条轨迹当一个整体计算单一的 episode 级 advantage，无法区分轨迹内哪些具体动作是好的、哪些是无效循环或走弯路——尤其是奖励往往只在回合结束时给出一次（稀疏/延迟奖励），信用分配问题被大幅放大。朴素的解法是对每个状态额外 rollout 多个候选动作来做 step 级比较（论文 Figure 1 中间），但这需要为每个状态做额外的 LLM 前向计算，且要为从未真正执行过的假设动作评估奖励，开销不可接受。

## 方法

核心问题：能否在保留 group-based RL 的 critic-free、低显存、稳定收敛这些优点的同时，为多轮 agent 训练引入细粒度的 step 级信用分配？

GiGPO 用两层分组结构回答这个问题：

1. **Episode 级相对 advantage（宏观）**：与标准 [[grpo]] 一致——固定任务 $x$ 和相同初始状态下采样 $N$ 条完整轨迹 $\{\tau_i\}_{i=1}^N$，用总回报 $R(\tau_i)=\sum_t r_t^{(i)}$ 归一化组内均值和标准差（或用固定归一化因子 $F_{norm}=1$，等价于无偏 leave-one-out 估计，用来缓解标准差归一化在长程任务里带来的"难度偏差"——低方差组，比如极难或极易的任务，会拿到不成比例的大梯度）。

2. **Anchor state grouping + Step 级相对 advantage（微观）**：这是本文的关键创新。因为同一批轨迹来自相同任务和相同初始条件，很多环境状态会在不同轨迹之间、甚至同一轨迹内部重复出现（比如反复回到同一个网页、同一个房间）。GiGPO 把这些重复出现的状态记为 anchor state $\tilde s$，纯离线地用哈希表把"在同一个 anchor state 下采取的不同动作"回溯聚合成一个 step 级组 $G^S(\tilde s) = \{(a_t^{(i)}, R_t^{(i)}) \mid s_t^{(i)}=\tilde s\}$，其中 $R_t^{(i)}=\sum_{k=t}^T \gamma^{k-t} r_k^{(i)}$ 是折扣回报（而非仅用即时奖励，因为稀疏奖励下即时奖励往往是 0）。同一个 anchor state 下不同动作的相对好坏，就用组内均值/标准差归一化得到 step 级 advantage $A^S(a_t^{(i)})$。

   这个机制不需要任何额外 rollout——它只是对已经生成的轨迹做事后的 key-based 分组，计算开销是哈希表查找+简单算术。

3. **合并**：最终 advantage 是两层的加权和 $A(a_t^{(i)}) = A^E(\tau_i) + \omega \cdot A^S(a_t^{(i)})$（$\omega$ 固定为 1，未调参），代入标准 PPO 式 clip 目标 + KL 惩罚。在极端情况下（没有任何状态重复，$A^S=0$），GiGPO 自然退化为 GRPO，因此下界性能有保证。

## 实验与结果

- **ALFWorld / WebShop**（Qwen2.5-1.5B/7B-Instruct，rollout 组大小 $N=8$，Table 1）：GiGPO（$F_{norm}=1$ 版本）在 1.5B 上比 GRPO 高 13.3pp（ALFWorld）、10.6pp（WebShop）；7B 上高 12.6pp、9.1pp。PPO（带 critic）反而不如 GRPO/GiGPO，说明 group-based 方法在这个任务规模上已经优于 critic-based。
- **Search-augmented QA**（Qwen2.5-3B/7B-Instruct，NQ+HotpotQA 训练，Table 2）：GiGPO 平均分 3B 42.1%、7B 47.2%，超过 Search-R1、ZeroSearch、StepSearch。额外发现：GiGPO 训出的策略工具调用更省——7B 模型单跳任务平均只需 ~0.9 次工具调用、多跳 ~1.6 次（对照 baseline 上限 3 次），作者把这归因于 step 级分组会识别并抑制"query1→info1→query1→info1"这类重复查询模式。
- **消融（Figure 4）**：去掉 episode 级 advantage 或去掉 step 级 advantage 都会显著掉点，尤其是 step 级 advantage 对 Cool、Pick2、WebShop 这类更复杂任务影响更大；$F_{norm}=$std 与 $=1$ 两个版本之间的差距远小于"去掉某一层结构"带来的差距，说明两层结构本身（而非具体归一化选择）才是收益的主要来源。
- **成本（Figure 6，唯一的系统开销数字）**：在 ALFWorld + Qwen2.5-1.5B 上，rollout + old/ref 概率计算 + 策略更新这些与 GRPO 共享的部分每轮花 362.83s；GiGPO 新增的 anchor state grouping（哈希表查找）只需 0.01s/轮，step 级 advantage 计算（简单算术）只需 0.53s/轮，合计占总训练时间 < 0.002%。GPU 显存和 rollout 成本与 GRPO 完全相同（同一个 actor LLM，无额外前向）。
- **Step 级组大小的训练动态（Figure 5，ALFWorld）**：训练全程 group size=1（无重复状态）的比例始终 < 35%，也就是 65%+ 的状态都能形成 step 级组；训练早期（iteration 10）大组（≥10）占比 > 20%，反映未成熟策略的重复/无效动作多；训练后期（iteration 140）组大小收敛到 6–8（接近 $N=8$），说明策略已经学会稳定、一致地完成任务。

## 局限与疑点

- **依赖精确状态匹配**：anchor state grouping 靠状态精确相等来分组，在状态空间连续或存在细微噪声差异的复杂环境里，重复状态可能很难被检测到，此时会退化为普通 GRPO（论文自己承认的下界）。作者提到用相似度阈值（longest matching subsequence > 0.9）做过缓解（QA 任务里用到），但更稳健的状态匹配（embedding-based 等）留作未来工作，未验证。
- **验证场景规模**：三个任务家族（ALFWorld、WebShop、search QA）都是相对结构化、状态空间有限的环境，还没有在 SWE-Bench 级别的长程、高维、非结构化编码 agent 场景上验证——这类场景里"完全相同的环境状态重复出现"的假设可能不成立（代码库状态几乎不会精确重复）。
- 论文没有报告不同 $N$（rollout 组大小）下 step 级组质量/收益的系统性关系，只用固定 $N=8$（agent 任务）或 $N=5$（QA 任务）。

## 对我们的启发

- **信用分配可以完全在 rollout 后离线完成，不占用额外算力**：GiGPO 的核心价值主张——步骤级信用信号只需要对已产生轨迹做哈希分组，不需要额外 LLM 前向——对我们设计训练管道有直接参考意义：只要我们的 rollout 执行层（沙箱/环境）能可靠地暴露"环境状态"这一抽象（哪怕只是字符串化的 observation），credit assignment 逻辑就可以完全放在训练侧后处理，不需要在执行侧做任何改动或增加调度复杂度。
- **和 [[agent-rl-credit-assignment]] 里 Agent Lightning 的对比**：GiGPO 与 LightningRL 的"恒等分配"是两种截然不同的 credit assignment 思路——LightningRL 把 episode return 原样分给每个 action（不区分好坏），GiGPO 通过"同状态下比较不同动作"给出有区分度的相对信号，且不需要额外训练或学习一个价值函数。如果我们平台要支持这两类算法，需要在 rollout 数据里保留"环境状态"这个字段（不仅仅是 LLM 的 input/output/reward 三元组），这是比 Agent Lightning 的 MDP 抽象更细一层的数据需求。
- **警惕适用边界**：GiGPO 的收益高度依赖"环境状态会在同一批 rollout 内重复出现"这个假设，这对 ALFWorld/WebShop 这类离散、可回退的环境成立，但对我们更关心的代码/沙箱 agent 场景（每次执行几乎不会产生完全相同的状态）可能收益有限，除非引入模糊匹配。评估这类方法时要先看任务的状态重复率，而不是直接照搬 ALFWorld 的结果。
- **可执行的 follow-up**：
  1. 调研 GiGPO 的相似度阈值分组（longest matching subsequence）在代码/工具调用类环境下的可行性，判断能否把 anchor state grouping 迁移到我们更关心的非结构化任务。
  2. 对照 verl-agent 开源代码，确认"环境状态"在实现里具体是什么粒度（原始 observation 字符串？还是经过某种规范化），这决定了我们的 rollout 数据模型要暴露到什么细节。
