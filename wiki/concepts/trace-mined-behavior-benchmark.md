# 从部署轨迹挖行为基准（Trace-Mined Behavior Benchmark）

## 一句话定义

从真实部署产生的大规模 agent 会话轨迹里，针对用户指定的某种"不良行为"自动检索出对应的决策点、切出上下文、生成 rubric，直接组装成可复用测试基准的方法；[[trace-mined-behavior-benchmark|TraceDance]] 是这一思路目前唯一的完整实现 [[2609.33295]]。

## 为什么对我们重要

现有 agent 基准（[[swe-bench-pro]]、[[terminal-bench]]）测的是"任务有没有做完"，但生产上更常出的问题是"任务做完了，过程里干了不该干的事"（泄露 token、悄悄关掉失败的测试、未确认执行破坏性命令）。这条思路直接对应我们平台需要补的一块能力：**把生产上已经发生过的具体事故，低成本地转成可以反复跑的回归测试**，而不是每次靠人工复盘、事后写死一条规则 [[2609.33295]]。

## 核心机制 / 主要变体

- **决策点延续（Decision-Point Continuation）**：不重放整条轨迹、不需要参考答案，只在目标行为附近切一刀，让被测模型接上写"下一步"，再用行为专用 rubric 打分。三种切法（Action 帧切在行为发生前、Failure 帧保留失败信息但删掉原响应、Claim 帧保留结果但删掉原声明），对应"该采取什么行动 / 该怎么应对失败 / 该基于结果说什么"三类问题 [[2609.33295]]。
- **Anchor-and-Confirm 两阶段检索**：可编程锚点（用工具报错、调用参数、事件顺序、关键词等结构化规则做 CPU 端粗筛）→ Fast LLM（轻量模型）做候选级语义确认，避免对全部会话跑重模型 [[2609.33295]]。
- **Anchor Synthesis Loop**：当预置规范不覆盖用户想要的行为时，强模型生成"锚点定义 + 确认准则 + 切割契约 + rubric"四件套 → 安全检查与代码审查 → 在真实轨迹上试跑校验 → 依据采样确认率反向调整锚点范围（确认率低说明太宽，候选太少说明太窄）→ 有限轮迭代收敛 [[2609.33295]]。

## 工程要点与数字

- 25.2 万条会话（Claude Code 编码场景 + OpenClaw 通用工具使用场景），构建出 107 个基准 / 4,125 个实例，95.3% 的目标基准构建成功；成功查询平均消耗约 552 次 LLM 调用，被拒绝的查询平均只需 1.3 次——**"确认某行为在数据里不存在"本身很便宜**，贵的是把它变成可用基准 [[2609.33295]]。
- 因为不需要环境重放，只需要"截断后的上下文 + rubric"，单实例运行成本显著低于需要完整环境状态还原的基准（如 [[recreation-bench]] 需要版本化 VM worker 重放） [[2609.33295]]。
- 人工验证：抽样 100 条实例，两名标注者都确认目标行为存在的比例 84%；自动分级器与人类 pass/fail 一致率 81.0%，同人类标注者互相之间的一致率（κ=0.40 vs 0.31）相当，但自动裁判系统性比人类更宽松（三评委均分 2.46 vs 人类 1.68）[[2609.33295]]。
- 九个前沿 LLM 在挖出来的基准上平均通过率仅 26.7%，"先检查再动手"这类行为通过率只有 8.1%，是当前模型最薄弱的环节 [[2609.33295]]。

## 开放问题

- 目标行为必须有可编程可观测的信号支撑检索；需要逐会话人工/LLM 细读才能识别的隐蔽行为，这套方法覆盖不到 [[2609.33295]]。
- 部署轨迹因保密协议无法公开发布，第三方无法用完全相同数据复现精确基准，只能复现方法论换自己的轨迹跑，可复现性天然受限 [[2609.33295]]。
- 自动分级器比人类系统性更宽松（+0.78 分），直接拿它做模型选型可能高估真实表现，需要显式的人类对齐抽样这道工序——这与 [[benchmark-item-validity-audit]] 强调的"verifier 可信度需要审计"是同一类问题在不同场景下的重现 [[2609.33295]]。
- 论文没有同类系统做头对头对比，"95.3% 构建成功率"等数字目前只能自证。
