# 混合 Computer-Use Agent

## 一句话定义

同时具备"操作图形界面"和"用代码/命令行构建软件"两种能力、且能在长程任务里交替使用两者的 computer-use agent（CUA），区别于只做其中一种能力的 GUI agent 或 terminal/code agent [[2609.22000]]。

## 为什么对我们重要

对应研究方向里"code / SWE / terminal / computer-use / GUI agent 的训练、环境合成与评测基准"这一关注点。这类 agent 的评测/训练环境比纯 GUI agent（如 OSWorld）或纯 terminal/SWE agent 重得多——需要同时提供图形运行时和构建工具链，直接影响我们平台需要支持的沙箱形态 [[2609.22000]]。

## 核心机制 / 主要变体

- **能力互补的动机**：GUI agent 能观察系统行为但很少构建或重配置界面背后的软件；terminal agent 看不到自己动作产生的界面反馈，没有探索性的视觉反馈。真实数字工作要求两者交替，而非首尾拼接 [[2609.22000]]。
- **应用复现（application recreation）任务**：给定一个可运行、source-blind 的参考应用，agent 必须探索其行为并实现功能对等的版本，只评估可观察行为而非源码结构；这个任务设计本身要求同时用 GUI 探索能力和代码实现能力，缺一不可，见 [[recreation-bench]] [[2609.22000]]。

## 工程要点与数字

- 已知模型在这类任务上普遍偏弱：即使总分最高的 GPT-6 Astra（58.06%），完整通过全部程序化测试的任务比例也仅 2.8% [[2609.22000]]。
- 多数轨迹在最后一次源码修改后不会重新启动并检查（"最终闭环"完成率最高仅 47.5%），说明当前模型"探索—实现"较强、但"验证收尾"普遍偏弱 [[2609.22000]]。

## 开放问题

- 目前唯一的系统性评测数据来自 [[recreation-bench]]，任务集中在"复现桌面/移动/Web 应用"这一种形式，是否能推广到更广义的"GUI+代码"混合任务（如运维、数据分析类工作流）尚待验证 [[2609.22000]]。
- 训练这类 agent 所需的沙箱基础设施（长时、有状态、桌面图形界面）与我们平台现有能力的差距尚未评估，见 [[2609.22000]] 笔记中的「对我们的启发」。
