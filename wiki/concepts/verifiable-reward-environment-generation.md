# 可验证奖励的 agentic 环境生成

## 一句话定义

为 agent RL 训练自动构造"环境动态 + 可验证结果奖励"配套齐全的训练环境这一类工程问题；核心矛盾是环境先行管线里动态与奖励事后对齐、容易错配 [[2609.27321]]。

## 为什么对我们重要

这是研究方向里"agent 轨迹数据、环境构造与可验证奖励的工程实现"的直接对应领域，也是我们平台如果要支持大规模 agent RL 训练必须补的能力之一：环境生成的成本、质量校验、可复现性直接决定训练数据供给的规模上限 [[2609.27321]]。

## 核心机制 / 主要变体

- **环境先行（environment-first）**：先构造环境 E，再事后定义结果规则 ℛ_E 并标注轨迹——这是现有主流管线的常见做法，容易导致动态与评测脱节、给 reward hacking 留空间 [[2609.27321]]。
- **机制先行（mechanism-first，VHD-Play 的方案）**：先采样求解一个数学模型得到参考解，再让语料落地渲染成有状态工具环境，奖励规则与环境动态共享同一个已求解的参考解，天然对齐。详见 [[vhd-play]] [[2609.27321]]。
- **skill-模板先行（skill-grounded，SkillGym 的方案）**：不构造数学模型，而是拿人写的 agent skill 库当种子，按子类手工设计可复用任务模板，再把每条 skill 实例化为环境；用"有/无 target skill 的对比执行"而非数学最优解来验证环境质量与奖励是否真的对齐该 skill。详见 [[skill-to-task-pipeline]] [[2609.27717]]。
- [[2509.02547]] Section 6.3 把这一问题定位为"环境规模化"这一 Agentic RL 前沿方向，指出主流环境（ALFWorld、ScienceWorld 等）不足以训练通用 agent 的共识正在形成，并总结出两条技术路线：① **自动化 reward 设计**——用辅助 explorer agent 生成轨迹数据集，训练奖励模型，把 agent 训练与人工 reward 设计解耦；② **自动化课程生成**——把环境本身变成"主动教师"，如 EnvGen 用环境生成器 LLM 根据 agent 弱点程序化生成新任务，形成"训练飞轮" [[2509.02547]]。
- [[2511.09586]] 把"自动化 reward 设计"这条路线进一步拆解为 [[gef-loop]] 反馈阶段的五个可规模化维度——密度、粒度、自动化、客观性、鲁棒性，并指出核心挑战是 [[generator-verifier-asymmetry]]：环境先行/机制先行两种范式本质上都是在解决"验证便宜、生成任务难"（易验证域）或反过来（易生成难验证域）的不对称问题 [[2511.09586]]。
- **"工具即数据库读写"环境先行方案（AgentScaler，[[2509.13311]]）**：把 function-calling 环境的构造问题转化为"工具依赖图建模（参数向量相似度 + LLM 校验边）→ Louvain 社区发现划分领域 → 每个领域生成数据库 schema + 可执行工具代码"的自动化流水线，从 3 万+ API 里划出 1,000+ 领域；验证靠数据库状态比对（write 型工具）+ 工具序列精确匹配（read 型工具）两个粒度，无需 LLM-as-judge 介入。是"环境先行"范式里少见的、给出完整自动化工具链（而非仅方法论）的具体实现 [[2509.13311]]。
- **三元组形式化 + agent 协作质检（DeepSeek-V4.1-Flash 的方案）**：把每个任务形式化为 (problem, environment, verification system) 三元组，用"难度"和"正确性"两个维度做奖励信号迭代训练模型自己构造任务，并在任务被 RL 消费后用产生的轨迹反过来做质量复审。Coding agent 场景下是多个专职 agent 接力的流水线：判断项目能否容器化构建与验证 → 选定起点/设计实现方向/产出 fail-to-pass 与 pass-to-pass 评测点 → 独立 agent 搭建依赖与工作目录、打包成新镜像层并抹除解答痕迹 → 多个 agent 尝试解题 → 独立质检 agent 复查环境与轨迹（环境问题、事实错误、评测点不匹配、可被 hack 风险）→ 不通过则由修复 agent 修正、重新进入验证 [[2609.19969]]。这条路线和 VHD-Play 的"机制先行"不同：不依赖任务能被形式化为数学模型，而是靠"真实交互数据先行 + 多 agent 协作质检收尾"来保证质量，覆盖面更广但质检成本更依赖 agent 能力本身。
- **参考先行（reference-grounded，[[recreation-bench]] 的方案）**：不构造数学模型，而是拿一个真实存在、可运行的参考应用/网站作为"标准答案"——agent 复现它，验证时用编排器探索参考应用生成"程序化断言 + VLM 视觉判定"双通道测试。这类方法适用于无法形式化为数学模型的开放式界面/软件任务，验证依据是"参考系统的可观察行为"而不是求解得到的最优解 [[2609.22000]]。
- **挖掘先行（mining-grounded，[[swe-rebench-v2]] 的方案）**：不构造/合成任务，而是挖掘真实 GitHub PR 历史当种子——每个仓库只用交互式 setup agent 推断一次安装/测试脚本并复用给该仓库所有任务，用修复前后成对执行提取 fail-to-pass 测试作为验证器,再用 LLM 裁判集成过滤 issue 清晰度。核心矛盾不是"动态与奖励对齐"，而是"语言/工具链异构性下的 setup 成功率"——即使有交互式 agent，单仓库单次 setup 成功率也只有约 20%。语言覆盖是这条路线的核心卖点（20 种语言、3,617 仓库），代价是任务分布完全由真实历史活动决定，无法像机制先行/skill-模板先行那样按需定制任务难度或类型 [[2602.23866]]。
- **代码先行（source-grounded，CodeMidas 的方案）**：连 issue/PR/commit/现有测试/书面文档都不要，只用源代码本身——删掉代码库里已实现的某个公共功能改造成开发起点，agent 在保留的参考实现上真实执行来构造行为落地的测试，原始实现本身就是参考解。核心矛盾是"任务专属输入降到零之后，怎么保证生成的任务和测试仍然可靠"：CodeMidas 用四道工序应对——execution 一致性检查（6 容器复检起始态必失败/参考解必通过）之后，再加三步 rollout 后过滤（对抗性 rollout 探测泄漏、复审 agent 核对 verifier 判定的假阳性/假阴性、剔除全通过/全失败任务）。是目前任务专属输入要求最少（Table 1 六项全免）、语言覆盖最广（23 种）的方案 [[2609.22068]]。
- **reward hacking 风险的直接量化（[[reward-hackability-audit]]）**：以上几条路线都在"环境先行容易给 reward hacking 留空间"这句话上语焉不详,[[2606.16062]] 给出了具体数字——对 SWE-bench Verified / R2E-Gym 这类被广泛用作训练素材来源的基准直接生成错误补丁实测,28.5%/25.0% 的任务能被 Docker 验证通过（即会为错误解发奖励）,并给出一套 **Docker gold-sanity gate**（生成的测试先在 gold 解上跑一遍再交给 LLM 判官）修复闭环,能以极低成本（$3.60 全流程）拦住 61.9% 的 LLM 判官系统性漏检的测试缺陷。这个 gate 组件与本页各条路线里依赖 LLM 生成测试/断言做质检的环节（SkillGym 的对比依赖测试、CodeMidas 的复审 agent 核验）是同一类问题的正交解法,原则上可以直接插入这些管线的质检步骤 [[2606.16062]]。

## 工程要点与数字

- VHD-Play 给出的具体成本基准：$0.01–0.03/条准入环境，3300 条环境全库成本约 $33–99 美元量级 [[2609.27321]]。
- 三重自动准入校验（可执行性 / 默认区间合法 / 最优点奖励一致）是保证生成环境质量的关键机制，避免人工逐条验证 [[2609.27321]]。
- SkillGym 给出的成本基准与 VHD-Play 统计口径不同，不能直接比：平均 **4.5 小时/任务**的人工+agent 混合构建成本（含手工模板设计），2,756 个准入环境；采样阶段还有单独的 17.4% 轨迹成功率（48,152 次采样仅 8,364 条通过 outcome verifier）[[2609.27717]]。
- SkillGym 的两级准入里，第二级不是校验"数值最优"，而是**对比 skill 依赖性**（有/无 target skill 结果是否出现 (1,0) 的翻转），这是与 VHD-Play 三重校验（偏数学正确性）不同的一种准入哲学，更适合非结构化、不可形式化成数学模型的开放式任务 [[2609.27717]]。
- AgentScaler 流水线规模：3 万+ API → 1,000+ 领域，但论文**未披露**构建这些领域/数据库 schema 的算力成本、耗时、单领域存储开销——与 VHD-Play 的量化成本形成对比，是这条"环境先行"路线里成本可见度的已知缺口 [[2509.13311]]。
- DeepSeek-V4.1-Flash 的两条产线未披露单条环境成本或全库规模数字，但明确了两个数据来源：coding agent 环境一部分来自内部/外部真实 coding agent 会话（按轨迹去重、过滤高复杂度或模型表现差的任务），另一部分来自达到 star 数阈值的公开 GitHub 仓库 [[2609.19969]]。
- [[recreation-bench]] 的双通道验证不需要预先形式化数学模型，但对基础设施要求更重：每个验证周期要跑一个版本化 VM worker 探索/重放参考应用，还引入 VLM 判定这一额外成本项（论文未披露测试生成阶段本身的成本，只披露了下游 agent 评测的资源消耗） [[2609.22000]]。
- [[swe-rebench-v2]] 给出目前这类环境生成路线里最完整的**多语言规模化成本核算**：21,692 个仓库跑 setup agent 共约 53.5 万次模型调用，折算约 $0.0873/仓库、总计约 $1.9K；任务级验证 583,809 次 Docker 构建、约 26,400 job-hours；最终 32,079 个环境的镜像总量 26.36 TiB（约 840MB/环境）。这组数字可以和 VHD-Play 的 $0.01–0.03/条、SkillGym 的 4.5 小时/任务直接对比：三者统计口径都不同（$/环境 vs 小时/任务 vs $/仓库+构建算力），但都指向同一个问题——环境生成成本的可比性缺一个统一的核算框架 [[2602.23866]]。
- CodeMidas 的任务/质量消融给出一条独立于成本数字的工程结论：高质量 3k 子集在 SWE-bench Pro / DeepSWE / CodeMidas Val 三个评测上全面超过未经清理/一致性检查/rollout 后过滤的未过滤 8k 样本，全量 5,545 优势更大（分别 +0.59 / +4.59 / +4.49pp）——说明质量过滤环节比单纯扩大候选池规模更值得优先投入算力，但 CodeMidas **完全未披露**其多阶段 agentic 质检管线（任务设计 + 测试构造 + 复查 + 6 容器一致性检查 + 对抗泄漏探测 + 4 次真实 rollout + 复审，逐任务跑一遍）本身的 $ 或算力成本，是目前几条路线里 agentic 计算投入看起来最密集、但成本可见度反而最差的一个 [[2609.22068]]。

## 争议与矛盾

（暂无跨来源分歧；九篇来源视角互补，未见结论冲突。六条主线各有侧重且适用场景不同，互为补充而非竞争：VHD-Play（机制先行）与 AgentScaler（环境先行 + 工具依赖图自动化）面向可形式化为数学模型或已有明确 API/工具边界的任务；SkillGym（skill-模板先行）面向 SWE/terminal/办公等不可形式化的开放式任务，用对比 skill 依赖性测试替代数学最优解校验；DeepSeek-V4.1-Flash（三元组形式化 + agent 协作质检）面向真实交互数据驱动的通用/coding agent 任务；[[recreation-bench]]（参考先行）面向无法形式化、依赖真实参考应用的开放式界面/软件任务；[[swe-rebench-v2]]（挖掘先行）不构造/合成任务而是挖掘真实 GitHub 历史，用语言覆盖面换取任务分布的可控性；CodeMidas（代码先行）把任务专属输入砍到只剩源代码本身，用四道工序（含 rollout 后过滤）换取"零外部记录依赖"下的可靠性，是挖掘先行之外另一条不依赖开发记录的路线，二者的核心取舍不同——挖掘先行靠真实 PR 历史换取任务的真实性但受限于 setup 成功率，代码先行靠"删除再重写"的构造方式换取语言覆盖面但依赖多阶段 agentic 质检兜底；[[2509.02547]]、[[2511.09586]] 则是站在更高层给出"自动化 reward 设计 / 自动化课程生成"的方法论综述与 [[generator-verifier-asymmetry]] 核心挑战框架，覆盖上述各条具体路线）

## 开放问题

- 目前 VHD-Play 的方法学证据局限于"可形式化为数学模型"的机制类任务（运筹/组合优化）。SkillGym 提供了一个部分回应：它用 skill-模板先行的路线覆盖了 SWE/terminal/办公等更开放式、不可形式化的 12 大类任务，但代价是准入校验从"数学上可验证"退化为"经验性的对比依赖测试"，无法像 VHD-Play 那样保证奖励与最优解精确对齐 [[2609.27717]]；两条路线在"可验证的严格程度"和"任务覆盖的开放性"之间做了不同取舍，谁更适合哪类任务尚无直接对照实验。
- 环境生成成本已量化，但配套的 RL 训练算力成本未披露，端到端（生成+训练）总成本仍不完整——VHD-Play 如此，SkillGym 同样只做了 SFT、没做 RL，问题依旧存在 [[2609.27321]] [[2609.27717]]。
- AgentScaler 的工具依赖图+社区发现方法能否在我们自己的内部 API 池上小规模复现，评估自动划分领域的质量和人工介入成本（follow-up，见 [[2509.13311]] 笔记）。
- DeepSeek-V4.1-Flash 路线的"agent 协作质检"本身的准确率/漏检率未披露——质检 agent 能在多大程度上真的拦住环境问题、评测点不匹配、可 hack 风险，缺乏量化 [[2609.19969]]。
- [[recreation-bench]] 的参考先行方案目前只用于评测基准构造，尚未看到把"程序化+VLM 双通道验证"直接接入 RL 训练奖励回路（而非离线评测）的实证 [[2609.22000]]。
- [[swe-rebench-v2]] 同样没有端到端 RL 训练消融，只验证了任务可执行、非平凡、pass@k 有提升空间等前置属性；而且主流水线出于成本只跑单次 setup 尝试，消融已证明多次重试能让成功率接近翻倍，说明当前 32,079 任务的规模本身还有明显未挖掘的空间，只是被成本权衡卡住 [[2602.23866]]。
- CodeMidas 的 rollout 后过滤（泄漏过滤、agent 解答一致性核验）完全依赖"复审 agent 的判断"，论文未报告这些判断本身的准确率/漏检率（人工抽检或多裁判一致性），也没有采用 [[benchmark-item-validity-audit]] 那种 oracle run / nop run / cheat-variant trial 三类主动探测 + 有序判定规则的系统性验证；"代码先行"的消融也只在单一基座模型（MiMo-V2.5）上做过，规模效应和过滤有效性能否迁移到其他模型未知 [[2609.22068]]。
