# 生产正确性 gap（Production Correctness Gap）

## 一句话定义

agent 生成的补丁能通过单元/集成测试等"局部正确性"检验，却在通过真实系统端到端运行时失败的现象；[[swe-serve]] 把这个差距正式量化为"去掉端到端（E2E）测试前后的 pass 率差"，实测达到 23.4 个百分点 [[2609.26777]]。

## 为什么对我们重要

这条结论直接对应我们最关心的问题：agent 在沙箱里"测试全绿"是否等于产出的代码在生产上真的能跑。它提醒我们，只用单元/集成测试通过率去衡量 agent 训练/评测效果，会系统性高估真实可用性，尤其是在有状态、长驻进程、并发访问的服务类场景下 [[2609.26777]]。

## 核心机制 / 主要变体

- 定义：production correctness = 满足任务行为要求 + 在推理系统里跑通 + 保持既有功能不被破坏 + 满足任务特定性能约束；不是"补丁通过测试"，而是"补丁在生产路径上正确" [[2609.26777]]。
- 测量方法：保留同一批 agent 生成的补丁和除 E2E 外的所有测试不变，只把 E2E 测试从评分中移除，对比移除前后的 pass 率差 [[2609.26777]]。
- 配对对照法：为排除"去掉任何测试都会让 pass 率上涨"这个混淆因素，作者额外做了"去掉同等数量、同角色（F2P/P2P）的非 E2E 测试"的随机化对照实验 [[2609.26777]]。

## 工程要点与数字

- [[swe-serve]] 19 个任务（627 个补丁）：完整验证器 pass 率 45.9% → 去掉 E2E 测试后 69.4%，**涨 23.4 个百分点**，11 个模型最佳配置无一例外全部上涨；bootstrap 重采样 95% CI 为 13.4–34.4 点 [[2609.26777]]。
- 配对对照：12 个可配对任务上，去掉 38 个 E2E 测试平均产生 16.1 次 fail-to-pass 反转，去掉同等数量非 E2E 测试只产生 8.0 次，**2.0 倍差距**；92.2% 的随机配对里 E2E 去除产生的反转数更多 [[2609.26777]]。
- Gemma 4 MoE 核心服务任务：33 个补丁中 16 个（48.5%）通过除 E2E 外所有测试，但未能正确加载官方 checkpoint、路由到 top-8 专家或跑通文本/图像服务接口 [[2609.26777]]。
- runtime-domain 广度：单域任务平均 pass 率 69.0% vs 多域任务 47.7%，差 21.3 个百分点，且多域任务在每个模型配置上都更低 [[2609.26777]]。
- 持久状态 / 并发协调（GPU 任务）：测持久状态的任务 pass 率低 20.8 点，测并发协调的任务（6 个）低 29.0 点；这两个差距在 CPU 任务和 DeepSWE 上都明显更小——提示差距主要来自"真实推理服务系统"这个场景本身，而非任务普遍更难 [[2609.26777]]。
- 提高 reasoning effort 能涨聚合 pass 率，但不能稳定缩小这个 gap，最大 effort 下差距依然显著 [[2609.26777]]。

## 争议与矛盾

（暂无跨来源分歧，仅一篇来源；论文本身承认该 gap 只由 E2E 测试和持久状态/并发测试代理定义，未覆盖可观测性、灰度发布、回滚等更广义的"生产就绪"维度）

## 开放问题

- 这个 gap 在其他推理系统（非 SGLang）、多 GPU/多节点场景下是否同样显著或更严重，尚无数据 [[2609.26777]]。
- 是否存在训练侧的干预（例如在 RL 奖励里直接引入 E2E 信号）能系统性缩小这个 gap，论文未涉及，是一个开放的训练方法论问题。
