# 视觉工作区

## 一句话定义

沙箱化多模态 agent 里"把视觉证据的生成和管理解耦"的状态管理模式：所有工具生成的图像先登记进图像账本（Image Ledger），但默认不进入模型上下文，只有被显式 Promote 到有界的活跃视觉上下文（Active Visual Context）后才会重新出现在下一轮请求里 [[2609.24362]]。

## 为什么对我们重要

我们平台上跑的 computer-use / GUI agent 每一步都会产生截图这类"视觉值中间证据"，如果直接照搬文本 LLM-in-Sandbox 的 append-only 做法（工具输出全部累加进上下文），会带来两个问题：上下文随轨迹步数无界增长（token 成本、推理时延）、关键证据被埋没在历史里。这个概念给出了一个**训练自由、可直接迁移**的通用解法，属于"沙箱与执行环境基础设施"里"多模态 agent 状态管理"这一具体子问题的参考设计 [[2609.24362]]。

## 核心机制 / 主要变体

- **问题背景**：LLM-in-Sandbox 范式（工具执行 + 持久文件 + 多轮推理）扩展到 VLM 时，视觉推理会产生裁剪图、掩码、叠加标注、放大区域等中间证据，这些证据不能像文本一样直接线性拼接进对话历史 [[2609.24362]]。
- **Image Ledger $\mathcal{L}_t$**：登记全部生成的视觉工件，赋予稳定 ID，记录文件位置与父子溯源；对非活跃、非输入的资产做**载荷驱逐**（图像数据从内存释放，只保留元数据）[[2609.24362]]。
- **Active Visual Context $\mathcal{C}_t = \{focus_t, aux_t\}$**：仅两个命名槽位，刻意设上限防止上下文随生成图像数量无界膨胀 [[2609.24362]]。
- **显式 Promote 操作**：$\text{Promote}(a, s)$，模型必须主动把某个工件提升到 focus/aux 槽位才能让它重新可见——**生成的工件默认在后续轮次不可见**，这是把"证据生成"（沙箱工具）和"证据管理"（Workspace）分离的关键设计 [[2609.24362]]。
- **请求编译**：最近 $k=3$ 轮完整保留，更早轮次用确定性摘要（Recap）压缩；只有活跃上下文里的资产被渲染成图像，其余仅以文字引用 [[2609.24362]]。
- **训练自由（training-free）**：框架不需要微调基座 VLM，完全依赖基座模型自身判断何时用工具、何时停止、哪些证据值得重新调入 [[2609.24362]]。

## 工程要点与数字

- 跨 7 个基准、4 个基座 VLM，VLM-in-Sandbox 的样本加权平均准确率均高于 Vanilla VLM 和 Append-only Sandbox；GPT-4.1-mini 上 Append-only Sandbox 甚至**低于** Vanilla（64.95% vs 65.81%），说明朴素累加视觉证据可能是负收益 [[2609.24362]]。
- 受控 2×2 消融（N=1,260）：相对"自动可见+无限保留"对照组，准确率 66.27%，token **少 18.6%**（p=0.014）[[2609.24362]]。
- 因子分解：仅"有界保留"贡献 +1.19pp、省 16.7% token；仅"模型主动选择"贡献 +0.56pp；两者叠加 +1.83pp、省 18.6%——**容量一旦被限定，"选择"改变的主要是看哪些证据而非看多少**，收益体现在准确率而非成本 [[2609.24362]]。
- 上下文规模增长对比（100 条轨迹，工件数 4→32）：无界保留 token 从 8.90K 涨到 42.30K；VLM-in-Sandbox 从 8.40K 只涨到 17.90K（可见派生图像数稳定在约 2 张）[[2609.24362]]。
- 推理侧：本地 vLLM + prefix caching 下，总 token −23.5%、首 token 时延（TTFT）−19.7%、端到端时延 −13.0%——**证据裁剪对已启用 prefix caching 的推理服务收益会被放大**，是独立于准确率提升的成本优化点 [[2609.24362]]。
- 活跃槽位数消融：2 槽（默认）准确率最高；4 槽 token 增加但无进一步提升；历史轮次预算超过 20 步收益饱和 [[2609.24362]]。

## 开放问题

- 只验证了静态图像推理；视频场景（保留时序证据、按需暴露相关帧/片段）作者明确留作未来工作 [[2609.24362]]。
- 训练自由框架高度依赖基座模型的自主判断，Qwen3.5-9B 上有 734 次挽回但也有 411 次退步，说明"模型自己决定何时用工具/何时调证据"本身不稳定，是否需要结合训练（而非纯 training-free）来收敛这种不稳定性尚未验证 [[2609.24362]]。
- Promote（模型主动选择）在挽回案例里只占 7.4%，多数收益来自"有界保留"本身——显式选择机制的边际价值有多大，需要更多场景验证 [[2609.24362]]。
