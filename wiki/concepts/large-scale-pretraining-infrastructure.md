# 大规模预训练集群基础设施

## 一句话定义

万卡级 GPU 集群上做稠密大模型预训练所需的硬件拓扑、4D 并行（TP+CP+PP+DP）策略与故障容错工程的组合体——核心矛盾是"同步训练对单点故障零容忍"与"万卡规模下故障是每日常态"之间的张力，靠自动化恢复、拓扑感知调度和细粒度 checkpoint 来化解 [[2407.21783]]。

## 为什么对我们重要

这是研究方向"训练侧系统工程（GPU 调度、checkpoint、弹性与容错）"最直接对应的生产级实证：Llama 3 405B 公开的故障率、根因分布和有效训练时间数字，可以直接作为我们评估自己调度系统容错目标时的行业基准线；4D 并行的网络拓扑感知设计思路（按带宽/延迟需求排列并行维度）也是我们做节点 placement 时可以直接借鉴的原则 [[2407.21783]]。

## 核心机制 / 主要变体

- **三层 Clos 网络拓扑**：机柜内 16 GPU 全互联（Minipack2 ToR）→ 192 机柜聚成 3,072 GPU 的 pod（满二分带宽、无超卖）→ 8 pod 聚成 24K GPU 集群（聚合层 **1:7 超卖**）。并行策略与调度器都对拓扑感知，尽量把通信限制在 pod 内 [[2407.21783]]。
- **4D 并行的维度排序原则**：`[TP, CP, PP, DP]`——按所需网络带宽从高到低排列；TP 限制在单机内（NVLink），DP（即 FSDP）放最外层，因为可以用异步预取权重/异步 reduce 梯度容忍更高网络延迟 [[2407.21783]]。
- **流水线并行的三处改造**：① 可调的连续 micro-batch 数 N（不再强制等于 PP 或总 micro-batch 数），在"大规模时 batch size 受限"和"隐藏点对点通信延迟"两种场景间找平衡；② 首尾 stage 各减一层 Transformer 层平衡显存/计算（embedding/loss 单独成层）；③ 交织调度 + 异步点对点通信降低气泡比 `(PP-1)/(V*M)` [[2407.21783]]。
- **上下文并行用 all-gather 而非 ring**：先 all-gather K/V 张量再计算本地 Q 的 attention；因 GQA 下 K/V 远小于 Q，暴露的 all-gather 延迟相对 `O(S²)` 的 attention 计算可忽略，换来更灵活支持 document mask 等掩码类型 [[2407.21783]]。
- **负载均衡与拥塞控制**：collective 库把单对 GPU 间通信拆成 16 条网络流（而非 1 条）配合 Enhanced-ECMP 哈希分流；spine 用深缓冲交换机吸收瞬时拥塞；最终 24K GPU 集群**不依赖传统 DCQCN 也能稳定运行** [[2407.21783]]。
- **故障诊断工具链**：PyTorch NCCL flight recorder（环形缓冲区记录 collective 元数据/调用栈，支持在线开关更细粒度 trace 而无需重启）；针对"功能正常但变慢"的 straggler GPU（一个就能拖慢上千张卡）的通信优先级排查工具 [[2407.21783]]。

## 工程要点与数字

- **规模**：Llama 3 405B 预训练用最多 16K H100（24K GPU 集群里取用），8 GPU/服务器，RoCE 或 Infiniband 400Gbps 互联 [[2407.21783]]。
- **MFU（Table 4）**：8K GPU（TP8/PP16/DP64，8K 序列长度）43%；16K GPU（TP8/PP16/DP128）41%（下降因 DP batch size 变小以维持全局 token/batch 恒定）；16K GPU + 128K 超长序列（CP16）38% [[2407.21783]]。
- **存储**：Tectonic 分布式文件系统，7,500 台 SSD 服务器、240PB，持续吞吐 2TB/s、峰值 7TB/s；核心挑战是 checkpoint 突发写入的瞬时带宽尖峰 [[2407.21783]]。
- **54 天故障统计**：466 次任务中断（47 次计划内维护，419 次意外）；约 **78%** 意外中断归因于确认/疑似硬件问题；GPU 相关故障占全部意外中断的 **58.7%**（Faulty GPU 30.1% + HBM3 Memory 17.2% + SRAM 4.5% + System Processor 4.1% + Silent Data Corruption 1.4% + Thermal 1.4%）；Software Bug 12.9%，Network Switch/Cable 8.4% [[2407.21783]]。
- **有效训练时间 >90%**，仅 3 次故障需要人工介入，其余全自动处理 [[2407.21783]]。
- **环境因素**：GPU 动态电压频率调节导致昼夜 1-2% 吞吐波动（中午温度更高）；数万 GPU 同步启停/checkpoint 可致数十兆瓦级电网功率瞬变 [[2407.21783]]。

## 开放问题

- 聚合层 1:7 超卖比对实际大规模 all-reduce/集合通信延迟的量化影响，论文未给数字，只说调度器会尽量减少跨 pod 通信 [[2407.21783]]。
- 故障统计（Table 4/5）仅来自 405B 主模型训练快照，8B/70B 等较小模型的基础设施表现是否有相同的故障率分布未披露 [[2407.21783]]。
- 数万 GPU 同步功耗瞬变对电网的冲击是论文明确承认"仍是扩展到更大集群的持续挑战"的未解决问题 [[2407.21783]]。
