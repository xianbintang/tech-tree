# SWE-rebench V2

## 一句话定义

语言无关的全自动流水线：挖掘 GitHub PR 历史、用交互式 setup agent 合成仓库级安装/测试脚本、经 LLM 裁判集成过滤，规模化构造覆盖 20 种语言、3,617 仓库、32,079 个可执行 SWE 任务的 RL 训练环境集合 [[2602.23866]]。

## 为什么对我们重要

这是我们关注的"agent 轨迹数据、环境构造与可验证奖励的工程实现"方向里一个**规模最大、语言覆盖最广、成本可量化**的样本：从中能直接读出多语言可执行 SWE 环境构造的成本结构（仓库级 setup 成本、镜像体量、构建算力）和质量控制方法（LLM 裁判集成过滤、失败模式诊断），是评估"我们自建类似训练环境需要多少基础设施投入"的一个具体基准 [[2602.23866]]。

## 核心机制 / 主要变体

- **仓库级 setup 复用**：每个仓库只在最新任务快照上推断一次安装/测试脚本，复用到该仓库挖出的所有任务，是控制多语言构造成本的核心设计 [[2602.23866]]。
- **交互式 setup agent**：mini-SWE-agent v1.14.4 + Qwen3-Coder-480B-A35B-Instruct，闭环调试（装依赖→跑测试→看报错迭代脚本），消融证明全面优于非交互式三步管线（甚至交互式 30B 模型能超过非交互式 480B 模型）[[2602.23866]]。
- **两阶段仓库过滤**：高资源语言（Python/Java/Go）用严格阈值（≥25 星、≥15 关闭 issue），长尾语言放宽（≥10 星、≥1 关闭 issue）；策略上只对约 20% 的仓库做昂贵的 setup synthesis，覆盖约 80% 的任务，setup 工作量降到 1/5 [[2602.23866]]。
- **执行验证 + 反 flaky 过滤**：多阶段 Docker 构建分离可复用 base 层与仓库专属层；修复前后成对跑全量测试提取 F2P 测试；每个候选任务重跑 3 次、结构化结果不变才保留 [[2602.23866]]。
- **LLM 裁判集成过滤（issue 清晰度）**：gpt-oss-120b / GLM-4.7 / DeepSeek-V3.2 三个独立裁判全部判定"specification adequate"才保留，配置（Verified-E）经 SWE-bench Verified 的 1,699 条人工标注校准，选择精确率优先而非最高 F1 [[2602.23866]]。
- **PR-based Task Expansion**：把未链接 issue 的普通 PR 也纳入训练集，问题描述由 LLM 基于 PR 描述+patch 合成（而非直接用原文），降低答案泄漏风险，并做泄漏检测后处理；作为"更大规模但置信度更低"的补充训练资源单独发布（120,000+ 任务）[[2602.23866]]。

## 工程要点与数字

- 端到端漏斗（Table 1）：2951.2 万 PR / 14.5 万仓库 → 含测试 859.4 万 / 10.2 万仓库 → 关联 issue 且含测试 80.6 万 / 5.08 万仓库 → 仓库级过滤后 58.4 万 / 2.17 万仓库 → 成功产出 F2P 任务 4.13 万 / 4,006 仓库 → issue 清晰度过滤后 3.30 万 / 3,701 仓库 → 3 次验证稳定 **32,079 任务 / 3,617 仓库**；issue 链接是仅次于"要求含测试"的第二大瓶颈，缩减近一个数量级，是引入 PR 扩展阶段的直接动机 [[2602.23866]]。
- 即使有交互式 agent，单次 setup 尝试的仓库成功率也只有约 20%；从 1 次增到 10 次尝试，成功率接近翻倍——主流水线出于成本-产出权衡只跑单次 [[2602.23866]]。
- 成本：setup agent 处理 21,692 个仓库，平均 24.67 轮交互/仓库，约 53.5 万次模型 API 调用，平均每仓库轨迹输入 ~21.4 万 token / 输出 966 token，折算约 **$0.0873/仓库**，setup 推理总成本约 **$1.9K**；任务级验证 583,809 次 Docker 构建，平均单次 2.71 分钟，累计约 **26,400 job-hours**；最终 32,079 个环境的 Docker 镜像总量 **26.36 TiB**（约 840MB/环境）[[2602.23866]]。
- 最终数据集：覆盖 2014–2025，中位数每任务修改 3 文件/34 行（90 分位数 9 文件/181 行）；20 种语言，Python 21.6%、Go 20.6% 领跑；PR 扩展集泄漏检查（509 个 SWE-bench Pro PR 抽样）：77.0% 干净、23.0% 存在一定泄漏、2.4% 明确解答泄漏 [[2602.23866]]。
- 诊断研究（300 任务 × 7 前沿模型 × 3 次跑，Table 6）：Claude Opus-4.5 pass@1/pass@3 最高（25.2%/32.7%），其后 GLM-4.7（21.3%/26.7%）、MiniMax M2.1（19.2%/27.0%）、Gemini 3 Flash（18.1%/27.7%）；识别出三类系统性混淆因素——测试耦合（P2P 回归，不一定是缺陷）、隐式命名要求（测试对实现细节有未言明要求）、外部依赖（问题描述引用可能失效/需鉴权的外部资源）[[2602.23866]]。

## 开放问题

- 端到端 RL 训练消融缺失：论文只验证了"任务可执行、非平凡、有 pass@k 提升空间、元数据能区分干净/混淆任务"等前置属性,过滤后 vs 未过滤课程对下游 RL 效果的直接影响未做实验 [[2602.23866]]。
- 单次 setup 的成本权衡意味着当前规模仍有明显产出空间（消融显示多次重试成功率接近翻倍），完整的重试次数-成本-产出边际曲线未给出 [[2602.23866]]。
- 诊断研究样本量有限（300/32,079，约 0.9%），三类混淆因素在全量数据集里的精确占比未披露 [[2602.23866]]。
