# Ingest-wiki：笔记 → 概念页

目标：wiki 是**跨来源的、持续演化的**知识，而不是笔记的复制。一篇笔记通常影响 2–6 个概念页。

## 步骤

1. 读刚写好的笔记，列出它涉及的概念（方法、系统组件、基准、问题）。
2. 对每个概念：
   - 在 `wiki/concepts/` 里用文件名和 `aliases` 搜索是否已存在（包括同义词、中英文）。
   - **已存在** → 更新：把本笔记的新事实并入对应小节，`sources` 追加笔记 id，`updated` 改为今天。
   - **不存在** → 只有当该概念足够重要（会被多篇笔记引用）才新建；否则只在笔记里写纯文本，不建页。
3. 确保双向链接：笔记正文 `[[concept]]` ↔ 概念页「相关来源」列出 `[[note-id]]`。
4. 发现与既有结论冲突（数字不一致、结论相反、适用条件不同）：写进「争议与矛盾」，并列出处，**不删除旧结论**。
5. 跑 `uv run python -m pipeline.wiki_lint`（如果能执行命令），修掉本次引入的断链。

## 概念页结构

```markdown
---
title: "..."
aliases: [...]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: [note-id, ...]
---

# <概念名>

## 一句话定义

## 为什么对我们重要
（站在 research_direction 视角）

## 核心机制 / 主要变体
（每条事实后标来源 [[note-id]]）

## 工程要点与数字
（成本、吞吐、规模、踩坑；标来源）

## 争议与矛盾

## 开放问题

## 相关概念
[[...]]

## 相关来源
- [[note-id]] — 一句话说明它贡献了什么
```

## 约束

- 保持概念页精炼：超过 ~300 行就拆子概念。
- 不捏造来源里没有的数字。
- 只改 `wiki/` 与对应笔记的链接部分。
